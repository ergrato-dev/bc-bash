# jq: leer y escribir JSON

**JSON** es el formato en que hablan las APIs y casi todas las herramientas modernas: `docker inspect`, `kubectl get -o json`, `gh pr list --json`. `grep` y `awk` lo leen mal, porque un JSON puede venir en una línea o en cien, con las claves en cualquier orden. `jq` lo entiende.

## Lo que es JSON

```json
{"host": "web-01", "servicios": [{"nombre": "nginx", "puertos": [80, 443], "activo": true}]}
```

**Objetos** `{"clave": valor}`, **arrays** `[1, 2]`, **textos** entre comillas dobles, **números** sin comillas, `true`, `false` y `null`. `"42"` es un texto y `42`, un número: no se suman igual.

## Filtros

`jq` aplica un **filtro** al JSON que lee y escribe el resultado. Los filtros se encadenan con `|`, como los comandos de bash:

![jq pasa el JSON por una cadena de filtros: .servicios[] saca cuatro objetos, select deja pasar dos y .nombre escribe dos textos](../0-assets/03-jq-filtros-en-cadena.svg)

```bash
jq . s.json                              # todo, sangrado
jq .host s.json                          # "web-01"
jq -r .host s.json                       # web-01, sin comillas: para bash
jq '.servicios[0].puertos[1]' s.json     # 443
jq -r '.servicios[].nombre' s.json       # el nombre de cada uno, uno por línea
jq '.servicios | length' s.json          # cuántos hay
jq -c '.servicios[] | select(.reinicios > 5) | {nombre, reinicios}' s.json
jq -r '.servicios[] | "\(.nombre): \(.estado)"' s.json
jq '[.servicios[].reinicios] | add' s.json   # la suma
```

- `.[]` saca **cada** elemento de un array por separado, y lo que va detrás se aplica a cada uno. `[ ... ]` vuelve a juntar los resultados en un array.
- `select(condición)` deja pasar lo que cumple la condición: es el `grep` de jq.
- `\( )` dentro de un texto pone el valor de un filtro, como `$( )` en bash.
- `-r` escribe los textos sin comillas; `-c`, cada resultado en una línea; `-e` sale con `1` si el último resultado es `null` o `false`. Un campo que no existe es `null`, no un error.

## Construir JSON

Escribir JSON con `printf` o `echo` falla en cuanto un valor lleva unas comillas, un salto de línea o una barra. `jq -n` lo construye sin leer nada, y los datos entran por opciones:

```bash
jq -nc --arg msg 'dijo "listo"' --argjson secs 42 '{mensaje: $msg, segundos: $secs}'
# {"mensaje":"dijo \"listo\"","segundos":42}
jq -ncR '[inputs]' < hosts.txt         # una línea por host: ["web-01","web-02"]
```

- `--arg nombre valor` crea la variable `$nombre` de jq con un **texto**, escapado.
- `--argjson nombre valor` la crea con un valor que ya es JSON: un número, un array. Si no es JSON válido, `jq` para.
- `-R` lee cada línea como un texto, no como JSON. Con `-n`, `inputs` son todas las líneas: `[inputs | ...]` las convierte en un array (`[]` si no hay ninguna).
- `tonumber` convierte un texto en número: `"200" | tonumber` es `200`.

## sed, awk o jq

| Si el dato es... | Usa |
|---|---|
| un texto que cambiar o filtrar línea a línea | `sed` |
| columnas: sumar, contar, elegir filas | `awk` |
| JSON, para leerlo o para escribirlo | `jq`, siempre |
| una variable o un par de líneas | bash: `${var//}`, `[[ =~ ]]` |

## Las trampas

- **Variables de bash dentro del filtro.** `jq ".[] | select(.env == \"$env\")"` se rompe con unas comillas y deja meter otro filtro. `jq --arg env "$env" '.[] | select(.env == $env)'`.
- **Comillas.** El filtro va entre comillas simples: dentro, `$env` es de jq y `"texto"` lleva comillas dobles.
- **`jq` construye antes de escribir.** Con `-n` y `[inputs]`, un error en una línea (un `tonumber` sobre `"-"`) para todo y no sale nada: arregla los datos antes de que lleguen a `jq`.
